# Матрица доступа к добровольной геолокации

Статус: обязательный контракт реализации. Наличие маршрута в OpenAPI само по себе не означает, что он уже реализован.

Любое разрешение действует только в своей области workspace/group. Владелец, администратор группы и обычный участник — обычные субъекты согласия. Нельзя включить передачу координат другому человеку административным действием.

## Порядок допуска

Активная сессия и устройство → активное членство → permission → направленное административное правило видимости → личное согласие субъекта на конкретного наблюдателя → entitlement → атомарный лимит.

Каждое условие необходимо. Для чтения собственных данных administrative edge не нужен. Администратор платформы не является участником семьи автоматически.

| Действие | Permission | Кто может выполнить | Дополнительные условия |
|---|---|---|---|
| Создать приглашение | members.invite | Владелец / назначенный администратор | members.max; код одноразовый и ограничен по времени |
| Настроить пары видимости | visibility.manage | Администратор соответствующей группы | Обе стороны состоят в группе; согласие не создаётся |
| Разрешить передачу себя | location.publish_own | Любой субъект, включая владельца | Только собственное устройство; явная аудитория; разрешение ОС |
| Пауза / отзыв согласия | consent.manage_own | Только субъект | Доступно независимо от платного тарифа |
| Читать текущую позицию | location.read_current | Разрешённый наблюдатель | Edge subject→viewer и активное согласие; read entitlement |
| Читать маршрут | location.read_history | Разрешённый наблюдатель | Отдельный scope истории; право сейчас и на момент точки; retention |

## Взаимное отслеживание

Для А и Б создаются независимые разрешения А→Б и Б→А. Для каждой пары субъект отдельно соглашается на передачу. Владелец А может включить разрешение видеть себя участнику Б, но участник Б должен отдельно согласиться на обратную передачу. Администратор разрешает Б→В; Б подтверждает передачу В. Вступление Г в группу не добавляет Г в существующие согласия.

Расширение списка наблюдателей создаёт новую версию согласия и новый интервал доступа; исторические точки до этого интервала не становятся доступны. Сужение аудитории, выход участника и отзыв действуют сразу для REST, WebSocket, кэша, истории, временных ссылок и отложенных уведомлений. Повторное согласие не оживляет старый интервал.

## Частота и хранение

Настройки платформы содержат интервалы получения/выгрузки, фильтр расстояния для idle/normal/live/sport/sos, порог батареи, предел оффлайн-возраста, размер батча и максимальное хранение истории. Изменения версионируются и аудируются.

`effective_interval = max(platform_mode_interval, entitlement_min_interval, subject/device_battery_interval)`

`effective_retention_days = min(platform_retention_cap, entitlement_retention_cap, subject_retention_preference)`

Отсутствующее entitlement не превращается в бесконечный доступ. Политика не отменяет локальную паузу и не запускает GPS. Сервер ограничивает чтение немедленно; физическое удаление выполняет плановый обработчик. У точки может быть несколько аудиторий с разными сроками, поэтому удаление одной аудитории не должно незаконно продлить её доступ либо удалить законно хранимую копию другой аудитории.

## Обязательные негативные проверки

- Оплаченный тариф / роль владельца без согласия не открывает координаты.
- Разрешение А→Б не открывает Б→А или А→В.
- Новое членство и новое согласие не открывают прошлую историю.
- Отзыв перед доставкой queued event блокирует событие; координаты не помещаются в общий канал группы.
- Подмена workspace, устройства или subject в батче отклоняется до записи.
- Конкурентное превышение лимита не проходит; повторный GPS или callback не списывает использование повторно.
- Админка и партнёрский кабинет не имеют скрытого доступа к маршрутам.
